# A05 courtyard golden evidence

`examples/courtyard-housing/expected/accepted-project/` is a byte copy of a real five revision project created by the current `archy` CLI from a fresh temporary copy of `examples/courtyard-housing/project.yaml`. It contains the exact source, accepted revision chain, run manifests, three generation variants and their three evaluations, subsequent evaluation/edit/restoration artifacts, full JSON and Markdown reports, event logs, and parameter files. No backend binaries or rendered images are part of this bundle. The empty runtime lock file was omitted; tests copy the bundle to a fresh root before opening it.

`evidence.json` records the actual CLI receipts, a SHA-256 and byte length inventory of every manifest artifact, manifest digests, the second independent generation receipt/inventory, and the measured metrics and check results of the three generated designs. `transcript.md` records the exact workflow and environment. The second project's run files are intentionally not bundled; the Cargo test recreates that run and compares its deterministic design and evaluation bytes to the saved first run.

Run `RUSTUP_AUTO_INSTALL=0 CARGO_NET_OFFLINE=true cargo test --locked -p archy-cli --test golden_artifacts`. The Cargo discovered test materializes the saved project in a disposable root with Git style `0755` directories and `0644` files. It confirms the storage reader rejects the copied managed directories at `0755`, then makes only that copy's `.archy/` and `runs/` directory trees private (`0700`) before verifying all five saved runs. No permission change is made to the tracked fixture, and storage security rules remain in force. The test verifies every saved file against its manifest and evidence digest, and executes the CLI against two new temporary source copies. It compares variant, evaluation, and generation JSON bytes exactly; checks measured metrics; compares serialized report JSON bytes after replacing only `context.run_id` and `context.parent_run_id` values; compares Markdown bytes after mapping execution IDs; and confirms edit/restoration leaves the first run's entire artifact inventory unchanged. The test never asks the storage layer to lock or mutate the tracked example.

Run IDs, idempotency keys, request hashes, revision record hashes, and report provenance bound to execution IDs vary on a new run. The saved bytes and IDs are authentic evidence of this capture, not universal expected IDs. A passing geometric check is not professional or regulatory approval. The bundle is a WSL core workflow fixture; native Omarchy and backend acceptance remain separate gates.
