# Optional independent IFC4 reader

This development verifier uses web-ifc 0.0.78 from the pinned npm lock. It reads bounded IFC, expected-fixture and canonical-source files, parses the IFC with a second engine, and prints one JSON report. It does not edit the model or publish a result. Node 22.22.2 is the tested development runtime; other Node versions fail explicitly. The local `node_modules` tree is ignored by Git; the package lock and separate loader/WASM hash proof remain available without staging installed third-party files.

Install with `npm ci --ignore-scripts --no-audit --no-fund`. Run `npm test`. For a single fixture, run `timeout 10s node verify.cjs fixtures/l_shape.ifc fixtures/expected.json l_shape.ifc fixtures/source/l_shape.json`. Run this command under an external process memory and output limit when inspecting untrusted IFC. The command itself limits IFC input to 8 MiB, expected JSON and canonical source to 64 KiB each, and web-ifc model memory to 128 MiB. It rejects nonregular input and symlinks. Parser wall time and whole-process memory still require an external supervisor.

The expected geometry comes from `tests/fixtures/analytic/courtyard-shapes.json`: a 10 × 20 m rectangle with 200 m² area and a 10 × 10 m L with a 5 × 5 m notch and 75 m² area. Both are translated to origin `[13,-2]` and extruded as three 3.2 m storeys. The two compact source JSON files encode those canonical values as exact UTF-8 bytes with one trailing newline. The reader checks their field agreement with `expected.json`, recomputes SHA-256 from the actual bounded source bytes, and compares that digest with the fixture and the IFC's source properties. The IFC files are curated exporter outputs with source properties rebound to these retained source bytes, including a repeated L export for GUID stability.

The supported subset is one IFC4 project, site, building, three schematic storeys and one extruded proxy per storey, with active SI metre/area/volume units, DRAFT provenance and the listed quantity set. The reader rejects other structures and mesh shapes. It checks placed geometry in IFC XYZ, closed winding, signed volumes, cap areas and the complete exterior top-cap boundary against the canonical footprint. It removes internal triangulation edges and accepts cyclic starting-point rotation or reversed winding, but requires the same boundary vertices within 1 µm. The pinned engine returns column-major placed transforms in a Y-up mesh frame; the reader converts that frame to IFC XYZ once. The numeric budget is the Task02 coordinate tolerance of 1 µm and its perimeter-derived area budget. This WSL evidence does not establish Omarchy interoperability or production acceptance.
