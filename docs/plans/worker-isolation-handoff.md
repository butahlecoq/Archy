## Plan and boundary

The first slice accepts a caller-held Linux Unix seqpacket control channel, receives one fixed `ARCHY-SCRATCH-1` frame with exactly one `SCM_RIGHTS` descriptor under an internal eight-second deadline, and requires `MSG_CMSG_CLOEXEC` without truncation. Rustix drops all received descriptors on rejection. The descriptor must be close-on-exec, an owned directory on tmpfs, with nonzero `statvfs` capacity at most **128 MiB and 256 inodes**, and `nosuid,nodev,noexec` mount flags. The public result is named `QuotaCheckedScratch`; it privately owns the `File` and exposes only read-only capacity values plus `as_file()` for the later bounded capture step. All failures use the existing `BACKEND_UNAVAILABLE` code with a specific scratch reason. The protocol marker is an internal candidate for the future packaged gate helper, not a change to Blender/IFC worker JSON.

This is a production-buildable **quota/descriptor receiver**, not a running supervisor or service identity check. A caller must still prove the channel belongs to the expected transient service, compare its MainPID/cgroup/effective limits, hold the start token until those checks pass, enforce namespace/bwrap policy, and prove inactive/empty cgroup and writer teardown before artifact capture. The fixed marker alone is not a per-job nonce or authentication. `QuotaCheckedScratch` does not grant semantic verification or publication authority. No service launcher, token sender, arbitrary command tool, or fallback was exposed in this slice.

The transferred [kernel probe](scratch-fd-probe-handoff.md) already passed real 64 KiB byte and eight-inode exhaustion, and the transferred [systemd user-service probe](systemd-scratch-fd-probe-handoff.md) already passed actual `--pipe` FD forwarding, effective cgroup/mount checks before its bounded start token, service collection, and retained-FD read on WSL. Their source hashes were verified after transfer; they were not rerun for this Rust receiver. They establish the kernel/user-manager mechanism on this WSL host, not Omarchy or a packaged worker.

## Round1 private mode fix

[Independent review](worker-isolation-review-round1.md) found that ownership, tmpfs type and mount flags did not check the directory's permission bits. A disposable copy of the systemd probe with `mode=0777` reproduced the finding: the service and probe exited 0 and reported `pass`. On the same WSL manager, a normal service FD had UID 1000 and exact mode `0700`; the parent real and effective UID were both 1000. The receiver now requires the FD's real-UID-owned directory to have exactly `0700` across permission and special bits. The service probe checks the received FD's owner and mode before releasing its token. This check establishes the recorded directory mode only; it does not authenticate a service or establish full isolation.

The test-first real seqpacket/FD regression `passed_directory_requires_exact_private_mode` initially exited 101: a mode `0777` directory proceeded to the filesystem quota check. It now passes for a `0700` descriptor and rejects `0777`, `0750`, `0701`, and `01700` with `BACKEND_UNAVAILABLE` and a private-mode reason. The `0700` case verifies that the receiver proceeds to its filesystem checks; it is not a positive end-to-end Rust quota acceptance test. The existing quota rejection fixture now explicitly sets `0700`, since the default umask created `0755` and made the first post-fix full suite fail at the new mode check. Its empty failed-run fixture was removed.
