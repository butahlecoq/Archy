## Verdict and finding

**One reproducible preference-policy gap.** `crates/archy-core/src/validation/v2.rs` checks a short list of command tokens and punctuation but admits a plain imperative command. The v2 brief with `preferences[0].value = "Please run rm -rf /"` returned exit 0 from `archy validate --json`; its canonical output retained that value. ADR 0006 says command-like instructions are rejected, and the release model treats imported descriptions as untrusted. The same validation is used on fresh v1 imports. This is a policy admission failure, **not** evidence of command execution: preferences remain passive in the exercised flow. Reproduce by copying `tests/fixtures/briefs/courtyard-v2.json`, replacing the first preference value with that exact text, then running `archy validate --project <copy> --json`. Expected: `INVALID_SCHEMA` at `preferences[0].value`; observed: `si-rectangle-v2` output with the command text. A bounded, explicit policy or a narrower documented promise is needed before accepting the advertised command-rejection contract.

**Independent MCP test limit:** `crates/archy-mcp/tests/parse_errors.py` treats `available >= max(1, pipe_capacity - 8192)` as evidence of stdout backpressure. A local `os.pipe()` reduced with `F_SETPIPE_SZ` to 8192 bytes gave `test_threshold=1` and `one_byte_satisfies=True`; the condition can pass before any writer blocks on that pipe size. This host's default pipe was 65536 bytes, so the observed stdio pass used a 57344-byte threshold. The test criterion issue is separate from A02's canonical v2 changes and is not repaired by this patch or by its passing Rust framing tests.
