## Findings and observations

1. **Bus request work is not explicitly bounded before credential/session checks (deployment blocker, no exhaustion reproduced).** `Review` accepts a `&str` body and performs the credential and logind round trips before checking the 64-character digest. There is no application-level incoming message cap, concurrent-call limit, or timeout on those async calls. In a disposable real bus with the actual served interface, a 1 MiB digest string reached the method and returned `org.freedesktop.DBus.Error.AccessDenied` in 0.023 seconds; 16 concurrent 1 MiB calls all returned AccessDenied, maximum 0.202 seconds, and the service remained alive. This establishes prevalidation allocation and work, not a denial of service. The bus daemon's own limits and production policy are unspecified in this worktree. Before enabling the service, bound incoming size/concurrency and verify resource behavior under stalled logind and a burst from a permitted human UID. The snapshot's output limit does not bound this input path.
2. **Session and disconnect races remain unproved on a native target.** `GetSessionByPID` takes a numeric PID; pidfd checks before and after reject a process that exits during lookup, but property reads are sequential and no atomic logind session snapshot or final post-snapshot session/connection check exists. A session can change after `Active` is read. This is not a demonstrated privilege bypass because `Review` only returns evidence and `Confirm` denies. A future decision must recheck the exact sender, process, session and protected head under the commit lock. The existing fixture has no mocked positive logind service; inactive/remote/forged properties, PID reuse during lookup, bus restart, and cancellation during a delayed lookup were not exercised end to end. No approval lease or disconnect signal handler exists to test for invalidation.
3. **The returned evidence deliberately contains untrusted and potentially sensitive source text.** `suggested_reason_unverified` is labelled, and the snapshot also includes input, normalized, variant, evaluation and comparison JSON. The exact bytes and SHA-256 are computed by the broker; output is capped at 1 MiB. This is suitable only for the enrolled review recipient under an effective system-bus policy. There is no caller-supplied actor, credential, secret, or raw internal error in the bus denial response. The current negative tests do not prove that a real installed policy restricts method access or that the trusted client safely renders control/bidi text in every snapshot field. Treat the policy and display as release gates, not as properties of this source slice.
