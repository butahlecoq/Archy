## Plan and boundary

The scoped plan was to accept a caller-held scratch directory `File` only after the caller has proved writer teardown; capture a fixed Blender or IFC inventory with descriptor-relative reads and strict bounds; bind bytes to the existing typed response claims; return owned bytes for later independent decoding; and keep declared worker failures distinct from malformed or missing success artifacts. This implements byte capture, **not** semantic geometry verification, sandbox isolation, or publication authority. There is no `VerifiedOutputs` claim or production launcher. The caller teardown, private scratch filesystem, quota and descriptor provenance preconditions remain for the future supervisor integration; the current test-only process helper does not supply them.

Public typed library entry points are `capture_blender(&File, &BlenderRequest)` and `capture_ifc(&File, &IfcRequest)`. They do not accept an executable, arbitrary path, or worker command. The successful result privately owns the raw response and exact claimed artifact bytes, SHA-256 values, and fixed producer/media metadata. A declared, valid worker error instead retains the bounded response bytes and typed `ArchyError`; optional known partial files are inspected only as untrusted scratch entries and never returned as accepted outputs. Unexpected/unsafe partial entries appear separately as `scratch_issue`. The worker error remains a failure whether or not that field is present. Missing, malformed or inconsistent success results return `ARTIFACT_INVALID` through the existing decoder/capture contract; a valid declared backend error keeps its declared error code.

The scratch inventory is exactly `response.json` plus five fixed Blender files or two fixed IFC files on success, with no extras. A declared error permits only a subset of those known artifact names. Each file is inspected with `O_PATH` and regular/single-link metadata before `O_NONBLOCK` read access. `openat2` uses `BENEATH|NO_SYMLINKS|NO_MAGICLINKS|NO_XDEV`; the response is capped at 1 MiB, each artifact at the existing storage 16 MiB bound, and captured bytes at 128 MiB total. Aggregate arithmetic is checked. After one bounded read per file, metadata and SHA-256/size claims are checked; a final directory inventory and metadata comparison detect changed entries. Returned bytes are owned and are never reopened by this API. The fixed inventory currently cannot approach the 128 MiB aggregate cap, but the cap is enforced independently.

## Remaining gates

The caller must establish whole-writer teardown and a private quota-bound scratch capability before invoking this API. Metadata checks detect observable replacements and writes; an ordinary same-size write within one filesystem timestamp tick can escape them, even without malicious timestamp restoration. They cannot prove absence of a live writer. Captured bytes and their hash remain internally consistent with the single read, but may be the pre-write bytes. A regular file on a hostile filesystem may still make an individual read slow; the proposed private bounded tmpfs and total supervisor deadline require separate integration proof. Independent PNG/GLB/IFC/.blend verification from these owned bytes, storage publication through `PendingRun`, actual cgroup/systemd/bwrap quota enforcement, and Omarchy acceptance remain open. This slice is frozen for independent review.

## Round1 Blender error provenance fix

Hume found that the Blender v1 declared-error envelope has no request, run, project, variant or digest fields. The same valid error response can be decoded with different supplied requests. The capture API now classifies that response as `ErrorBinding::UnboundDiagnostic`; `bound_error()` returns `None` and only `diagnostic_error()` exposes its parsed worker code. The bounded raw bytes, SHA-256, typed diagnostic and separate scratch issue remain available for quarantine or troubleshooting, but the Blender code is not authenticated job evidence. No caller context is copied into that response, and no Blender wire protocol or worker changed. The existing IFC error decoder compares its identity fields to the request; its captured failure is `RequestBound` and `bound_error()` returns the typed error. Success capture paths remain as before.

The new regression gives the **same Blender error bytes to two distinct typed requests** and requires unbound classification with no bound error for both. A distinct IFC request must reject the otherwise valid IFC error as `ARTIFACT_INVALID`. The new test first failed to compile because `ErrorBinding`, `binding()`, `bound_error()` and `diagnostic_error()` were absent, then passed after the API change. The old generic `error()` accessor was removed so callers must choose the bound or diagnostic path.

## Publication fixture correction and current source

The isolated publication gate log `/tmp/archy-core-publication-gates-round2.log` recorded exit 101 at `artifacts::tests::late_same_size_write_and_device_metadata_are_rejected`: `unwrap_err()` received `Ok(ReadFile)` with original `before` bytes and hash. Its same-size callback write and the pre/post `mtime`/`ctime` had the same nanosecond value `595452253` on tmpfs, despite a 2 ms sleep. This was a fixture assumption failure, not evidence that the owned bytes or their hash changed. A same-size write within one filesystem timestamp tick can be invisible to the metadata checks. The caller's proved writer-teardown precondition is required even for ordinary late writers; timestamp restoration is not the only escape.

The test-only callback now writes `after!` and uses `std::fs::FileTimes` to set an explicitly distinct mtime (`UNIX_EPOCH + 1 second`). It then tests rejection of an **observable** late mutation. There is no sleep, retry loop, second byte read, production capture change, protocol/API change or dependency change.
