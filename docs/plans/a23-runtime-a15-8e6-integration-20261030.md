# A23 runtime and A15 pinned-reader integration

This isolated candidate is based on published 8e6c8987431a3c613563345ee38f95f530181b12 and combines it with the frozen A23 historical retry candidate tree 4f51f707016e8d2c2ba2b630fc8bf8d91b93acb8. A15's MCP server still uses its pinned BoundProjectRead; CLI opens a new reader and then shares the same export body. The A15 preliminary accepted-history key scan and the locked authoritative key and conflict checks remain in place. CLI open, pinned snapshot/head, A15's preliminary scan and source verification map backend timeout/unavailable errors using the supplied key and revision before the authoritative lookup, without asserting publication. Post-publication errors retain their resolved identity. Unrelated error codes remain unchanged. The message explicitly refers to the authoritative key lookup because the preliminary A15 scan may already have run.

The MCP server opens its pinned reader at startup, before a request and key exist. For a legacy source whose accepted head needs the unavailable runtime, startup can fail before a request can receive a retry identity; restore the runtime and restart the server. This integration does not claim otherwise or change binding semantics.

The packaged worker verify.py SHA-256 is 9cc09fdae0693766cfefb7a5f2ff09086994d5555be8b2fa8050500727161c3a, and packaged verifier files match the pinned test reader. Runtime source identity is ae620ba494bef9e7639200e00e29ba1128bce840c13df460c773ac1d96880abc with build_ready false. A12 and distribution trusted review allowlists are empty. Published MCP, schema, A23 acceptance tests, skill and playbook paths are untouched by this overlay.

The earlier A23 historical retry and hwcaps follow-ons passed their narrow reviews; those reviews do not approve this integration. The A15 error path is covered by a focused pinned-reader test which lets head verification complete and injects timeout/unavailable at the next history scan. Removing the scan's retry mapping produced nonretriable BackendUnavailable; the test passes with the mapping. Injection is test-only. The A15 key-reuse, destination, project-binding and MCP contracts also require the checks recorded below.

The detailed predecessor handoffs retain the deadline fixture, native historical retry, ELF, signed package, Blender CPU and MaterialX evidence. In particular, a conservative ordinary-directory requirement rejects inactive or active hwcaps-only dependencies, ancestor-only RPATH and the observed MaterialX import-order case; it is not full dynamic-loader or arbitrary dlopen coverage. Missing libraries and full native source/notice closure remain unresolved. The 180-second end-to-end budget, A12 broader security safeguard, target Omarchy, full CPU golden journey, optional GPU and human acceptance remain open. This candidate is not a final package, host installation, release or distribution approval.

The offline CLI/MCP/gate Rust suite reported 122 passed and six ignored, including the 65-edit history stress case; some native-named tests return early without their optional fixture. They use test-only error injection and the development Python/pinned JS reader, not an installed Arch runtime.
- The real MCP export contract passed its absent-backend branch: repeated MCP calls and CLI returned matching errors without a fake receipt or revision; it also checks malformed requests, stale/key conflicts, destinations and project rebinding. Its successful installed-backend branch was not exercised.

These do not establish the full service budget, target or package installation.
