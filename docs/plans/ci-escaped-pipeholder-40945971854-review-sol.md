# Independent review: CI escaped pipeholder fixture

## Verdict

**Changes requested.** The correction improves the ordinary path but does not guarantee the escaped child is in a separate session, pinned by a pidfd, and acknowledged **before** capture can send its first group signal. `capture_with_term_pause` starts its 250 ms wall clock in the capture thread; the test thread calls `EscapedFixture::pin` only after spawning that thread. The two events have no ordering edge. A delayed test thread lets capture time out and signal the live shell group leader before release. The test then fails despite a correctly working capture implementation. The proposed repair therefore cannot yet be treated as a reliable fix for the red PR CI.

The normal test checks `Outcome::TimedOut`, `leader_pinned_at_group_signal`, `direct_reaped`, and an open pipe. Those assertions remain, but their intended ordering coverage is not assured: `leader_pinned_at_group_signal` is ORed at later KILL attempts too. If TERM killed the leader while it waited for `ack`, a later group signal can set the flag after that exit. The delayed-handshake probe reached the final missing `escaped:` output assertion, showing the earlier pin/reap/EOF assertions had passed in that run. This is a false positive for the intended “leader already exited before first group signal” case.

## Fixture and cleanup review

- The child writes its PID from inside the `setsid` shell and waits for `ack`. `/proc/<pid>/stat` is split after the command field; index 3 of the remaining fields is session ID. Comparing it with the PID proves separate-session leadership at the point of the read. The test checks a non-zombie state both before release and after capture returns. Under the ordinary path, it retains a pidfd until `EscapedFixture::drop`, and the guard signals that fd instead of a numeric PID. This avoids PID-reuse signaling **after a correct pidfd has been acquired**.
- The pidfd is absent until `pin` succeeds. If readiness times out, reading/parsing the PID fails, or `pidfd_open` fails, `Drop` only writes `ack` and removes the directory. If a child is already waiting, that acknowledgment can let it exec `/bin/sleep 10` with no retained fd to kill it. That is not safe cleanup on all failure paths. The five second wait and ten second sleep eventually bound this case; they do not make it immediate or prove no orphan during the interval. If the child exits before `pidfd_open`, a numeric PID could theoretically be reused before the fd is opened; the later session check is not an identity proof across that gap. No reuse kill was observed in these runs.
- The capture loop still uses `waitid(...NOWAIT)` and `try_wait()` to pin and reap its direct child; the normal test asserts direct reaping. The 1.2 s pause is reachable only through this module, which `lib.rs` includes under `#[cfg(all(test, target_os = "linux"))]`; `capture` calls the new helper with `Duration::ZERO`. Production builds do not include `process.rs`, so this seam does not alter production runtime behavior. The pause itself exercises delayed post-TERM capture, but does not fix the pre-TERM handshake ordering.
