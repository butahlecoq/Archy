## Input and output contracts

- `export_ifc(ExportIfcInput)` selects an explicitly requested accepted generation/edit run and variant, or the latest accepted generation/edit when `source_run` is absent. The selected run is verified before dispatch and again under the publication lock. A variant absent from that run is rejected.
- Accepted historical v1 and canonical v2 sources, in JSON or YAML, retain their exact input bytes and `source_format` in the export run. The original input SHA-256 is the worker's `source_digest`, the IFC `CanonicalInputSha256` property, the request's input digest, and the design manifest's `source_input_sha256`. The normalized SHA-256 is separate and comes from the verified source run. Neither value is manufactured from a substitute source document.
- Core's verified `NormalizedSpec` numeric view feeds the typed `IfcRequest` and evaluation; v2 exports use `evaluate_variant_v2`, while historical v1 uses the existing legacy evaluator. The worker protocol stays `ifc-worker-v1`: variant schema and geometry are already normalized independently of the brief's source format. No YAML or prose is parsed by the IFC worker.
- The export stores the verified source, normalized snapshot, selected variant, evaluation, real worker response, validation artifact, and exact IFC bytes. A canonical v2 export also stores its source-derived `profile.json`; historical v1 keeps its historical inventory. Re-verification compares the export and parent canonical state, source bytes, format, normalized snapshot, profile, evaluation, claims, and artifact inventory.
- The reader receives a fixed length-framed expectation derived from the verified Rust types, the original source bytes, and the actual IFC bytes. For canonical and YAML sources it verifies the exact source file identity and SHA-256 without reinterpreting text. It verifies the IFC graph, provenance, quantities, DRAFT state, footprint, placed closed meshes, area, elevations, and volume against the typed expectation. Historical v1 JSON retains its prior source-content checks.
- The original source frame is bounded at 1 MiB, matching the core parser; expected JSON is bounded at 16 KiB, IFC at 8 MiB. The existing fixed runtime pins, bubblewrap policy, process limits, and wall deadline remain in force. Production runtime installation on Omarchy remains a separate acceptance gate.
- Worker errors and independent verifier failures publish no accepted export; retry with the same key can succeed. Replay verifies the stored export and does not run the worker. Publication stays schematic `DRAFT` and creates no approval event.
