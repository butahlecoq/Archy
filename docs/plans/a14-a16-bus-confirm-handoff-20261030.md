The source and tests for `ProtectedProject`, `PinnedBusPeer`, and protected ingestion were carried into this worktree. The target's newer accepted worker, A09 and MCP modules were kept. Only the `verify_history` visibility export and bounded core history reader changed in overlapping source. The target workspace pins `rustix =1.1.4`, so authority uses that already locked version instead of the older writer worktree's 1.1.2. The older freeze is historical evidence for the **input**, not a hash of this integrated worktree.

New `HumanBus::Review` takes a proposal digest and the D-Bus method header's **unique sender**, queries `GetConnectionCredentials` for that name, requires UnixUserID, ProcessID and ProcessFD, checks kernel pidfd identity/liveness, and rejects agent/broker/root or non-enrolled UIDs. It asks logind `GetSessionByPID` and requires an active, local, seated `user` session owned by the same UID. It rechecks the process and connection credentials before reading the broker proposal and recomputing a protected snapshot. It returns the exact snapshot UTF-8 bytes and SHA-256 digest. Missing bus/logind fields fail closed. No bus connection peer UID is used as the method caller.

`HumanBus::Confirm` always returns AccessDenied. There is no authorization argument, mock authorization shortcut, or decision side effect. Existing `OP_DECIDE` remains denied on both seqpacket channels; the journal is opened by `archy-human-busd` only to verify it and is never appended by this service. This preserves DRAFT IFC status. The bus binary is broker-UID-only, uses fixed account/enrollment/state paths and the system bus, and is **not staged or activated** by the package. It cannot run as a production service on this development host without the fixed accounts and system policy.
