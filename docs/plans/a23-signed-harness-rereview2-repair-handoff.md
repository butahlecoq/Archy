## Exact changes

- Reviewed record JSON is parsed from the same bounded bytes sent to `gpgv`. Manifest, policy and transaction JSON are parsed from the same bounded bytes whose digest or trust checks were applied. Evidence artifacts and target files are read through descriptor-relative, no-follow regular-file opens. A read detects changes to its opened inode during the read. The detached signature and administrator keyring stay open through `gpgv` using inherited `/proc/self/fd` descriptors, so path replacement cannot select different signature/keyring bytes during that call.
- System trust paths still require root ownership and no group/world write permission, checked on opened components. Evidence and signature paths reject symlinks in every component. Record, manifest and artifact limits are 8 MiB, 1 MiB and 1 GiB respectively. Policy, transaction and detached signature limits are 1 MiB; the keyring limit is 8 MiB. Open signature and keyring metadata are checked again after `gpgv`.
- The policy maps uppercase full **primary certificate fingerprints** to human IDs. `gpgv VALIDSIG`'s first fingerprint is the actual signing key; its final fingerprint is the primary certificate. One valid status is required. The report includes both fingerprints. A subkey-only policy entry cannot authorize the primary. A real primary signature and a real signing-subkey signature are covered by tests.
- The verifier checks all evidence twice, then requeries installed packages and rechecks source HEAD/tree/cleanliness, spec, matrix, compatibility, archive, package, binary, locks, workers and transaction marker, followed by host identity. This detects the tested mutation during the scan. These independent reads are not an atomic snapshot. A writer can change files after the last check, or arrange an adversarial change-and-revert between checks. Keep evidence immutable, source and installation quiescent, and rotate the marker for each transaction; the verifier cannot prove the administrator rotated it.
- G04, G10 and C06 now identify existing fixture test commands, expected process exits and named checks. Accepted target geometry, installed fault injection and native containment remain deferred until executable candidate-specific commands and actual target artifacts exist. G08 and G09 remain deferred for unavailable production actions and human control.
