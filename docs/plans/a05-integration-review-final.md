# A05 end-to-end requirements audit

**Decision:** The current WSL workspace demonstrates the A05 local generate/evaluate/report/edit workflow against the reviewed contracts. **Issue 5 is not ready for closure or release acceptance:** the golden evidence and Cargo test exist locally but are not yet recorded by Git, and actual Omarchy/filesystem acceptance is deferred. No product source was edited, no commit or push was made, and no issue state or approval was changed in this review.

## Acceptance boundary

I read the current [open issue 5](https://github.com/butahlecoq/Archy/issues/5) through `gh issue view 5`, `task-03.md`, the final storage/CLI/report/golden handoffs and independent rereviews, the saved evidence/transcript, and the current CLI, storage, verifier, report and golden-test interfaces. Issue 5 asks for immutable snapshots and results, deterministic repeat runs, failed-design retention, revisioned no-overwrite recovery, edit provenance, and authentic acceptance evidence. It also says WSL/CI cannot establish actual Omarchy or human acceptance. Native backend and plugin work are outside A05.

## Actionable acceptance gaps

1. **P1 evidence publication — the required golden bundle is not checked in.** `git ls-files examples/courtyard-housing/expected tests/golden crates/archy-cli/tests/golden_artifacts.rs` returned **zero paths** on this review snapshot; `git ls-files --error-unmatch crates/archy-cli/tests/golden_artifacts.rs` also failed. `git status --short -uall` lists the golden files as untracked (63 paths under `tests/golden` and the expected-project tree). The local test passes because those files are present in this workspace; a clean checkout at the current repository revision cannot run or audit it. Record the exact fixture, evidence, transcript, scoped ignore override and Cargo test in the eventual reviewed change, then verify from a fresh checkout or equivalent staged tree. This is a publication/evidence gate, not a claim that the captured bytes are fabricated or that the local workflow fails. This review has no authority to stage or commit them.
2. **Target and recovery-evidence limits — do not promote WSL evidence into release acceptance.** The storage handoff gives a documented synthetic interruption/replay example and the tests exercise its control flow, but there is no saved sudden-power-loss or real `fsync` transcript; the task-03 plan's stronger crash/replay transcript artifact is not in `tests/golden/transcript.md`. Keep that distinction explicit when packaging the final evidence. Actual Omarchy execution and target filesystem behavior remain deferred by issue 5's closure contract. These limits do not negate the local deterministic workflow.
