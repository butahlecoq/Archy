## Review decision and mandatory A02 gate

The current tree has only the historical `si-rectangle-v1` normalized wire profile and `parse_project_v1`. It cannot distinguish an authentic old v1 record carrying a `claimed_regulation` marker from a fully rewritten and rehashed new record claiming the same historical profile. The reviewed binder intentionally permits the former. Therefore this integration does **not** claim a non-downgradable new-run policy or release readiness. A local full-history rewrite has no external trust anchor; hash-chain recomputation alone cannot establish original publication time or provenance.

Integrate A02 canonical v2 at the input admission and immutable run boundary before publishing new runs:

1. Parse newly submitted source with the A02 v2 parser and persist a canonical v2 normalized snapshot. Select the v2 profile from the accepted operation and parser result, never from a caller-provided normalized label or evaluation artifact. For a new `generate`, including claimed-regulation input, v1 is not an available profile. Reject source/profile disagreement before `begin` or publication. Keep an unchanged-key replay tied to the verified accepted run.
2. Put source schema, normalization profile, evaluation version, and report version in the immutable run record or a versioned profile record covered by its artifact inventory and revision. Define the allowed tuple for each operation: new `generate` uses canonical v2 and authority v2 when a claimed constraint exists; `edit` inherits its verified parent profile and uses its corresponding evaluator; `evaluate` inherits its verified source profile and uses its corresponding evaluator. For ordinary constraints, decide and document whether canonical v2 uses a separate evaluator/report pair even when checks have v1 geometric semantics. Never infer the tuple from an unverified child evaluation label.
3. In `verify_run`, dispatch first by the *verified stored profile and operation lineage*, reparse the stored source under that exact parser, compare the canonical normalized bytes, then recompute evaluation and report under the allowed tuple. Keep exact historical v1 generation, evaluation, report and marker replay for accepted old records. Do not let a child operation change profiles. Keep A03 diagnostic generation dispatch and variant identity.
4. Expose decision binding only after `verify_run` supplies the actual normalized, variant, evaluation, comparison, revision and head bytes. The structural `claimed_checks_passed_against` function alone cannot decide historical eligibility. A v2 claimed source must contain every required `authority:<id>` UNKNOWN check with null measurements and limits; geometric PASS/FAIL remains independent, and aggregate required status remains false.

Regression gate: publish a fresh claimed-regulation source; assert its stored immutable profile is v2 and its evaluation/report are authority v2 with required UNKNOWN. Attempt to submit or replay a v1 profile label for that fresh source, or to rehash its normalized/evaluation/report artifacts as v1; verification must reject it. Copy an authentic historical accepted v1 marker chain and assert exact byte replay, including the old report, still succeeds. Test `generate`, `edit`, and `evaluate` dispatch separately, unchanged-key replay, and compare plus binder on the actual accepted revision. The deliberately accepted full-chain rewrite limitation remains documented until an external anchor exists.
