## Findings and checks

- `ProjectStore::read_history()` calls the same `revisions_from()` validator as `LockedProject::revisions()` without locking, creating, recovering, or syncing. The validator uses pinned, descriptor-relative, no-symlink reads, private managed-directory checks, bounded files and inventory, sequential revision and receipt hashes. Missing `.archy` yields genesis revision zero; an existing `.archy` missing `revisions` fails as `ARTIFACT_INVALID`. `AcceptedHistory` retains its revision prefix and head hash after an append; selected `read_run()` reopens and rechecks recorded bytes. The locked writer's bootstrap, publication, sync, and recovery flow remains in its existing path.
- `desktop_status()` binds a cursor to the pinned root identity, current project ID and source digest, accepted revision, head hash, and offset. It enforces page size 1–100, defaults to 20, and returns `REVISION_CONFLICT` on a stale or foreign binding. It verifies every returned run and the selected run against the current project ID. `verify_history()` traverses accepted ancestry and recomputes canonical source, generation, variants, full evaluation results, reports, and events. A rehashed false evaluation with updated manifest and revision hashes is refused by a test. The response exposes bounded metadata only; it does not emit artifact bodies.
- Capabilities advertise only `project_status` and `run_status`; backend jobs are explicitly `unknown`. Artifact IDs and integrity values are informational and provide no opener, launcher, or job authority. Source-derived desktop schemas and all three fixtures are registered in the checker; the accepted fixture comes from a disposable private copy of the real saved chain.
- The actual transport module serializes with `serde_json` first, then escapes every non-ASCII scalar as JSON UTF-16 `\u` units, including surrogate pairs. Thus every split of emitted doctor/desktop JSON remains ASCII and the parsed Unicode value survives. Existing ASCII serializer output is byte-identical. CLI dispatch applies the helper to doctor and desktop success and compact JSON errors; persisted run, report, and A05 golden serializers are outside this change.
