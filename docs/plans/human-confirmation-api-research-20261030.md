# Human confirmation API research

This note refines the pending authority design; it is not an implementation or evidence of human authorization. On this WSL development host, `systemctl --version` reports systemd 259 and `pkcheck --version` reports polkit 127. The current locked Rust dependency graph contains rustix but no D-Bus or polkit client crate. Omarchy package and effective-policy support remain untested.

- The [D-Bus credential method](https://dbus.freedesktop.org/doc/dbus-specification.html#bus-messages-get-connection-credentials) returns whatever credentials the bus can determine; keys may be absent. `ProcessFD` can pin the peer against PID reuse when supported, while numeric `ProcessID` alone can be reused. A broker must reject missing required credentials, bind lookups to the unique sender, verify any received descriptor, and test the actual bus and kernel. Do not assume a particular bus supplies `ProcessFD`.
- The [logind manager interface](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.login1.html) exposes `GetSessionByPID`; the documented method takes a numeric PID. A race-safe relationship between a pinned process and that session lookup must be designed and tested rather than inferred from the existence of a pidfd. Active/local session facts must be rechecked at commit.
- [Polkit authorization results](https://polkit.pages.freedesktop.org/polkit/eggdbus-interface-org.freedesktop.PolicyKit1.Authority.html) distinguish authorization, a possible challenge, retention and dismissal. A final authorized result by itself does not attest that a fresh prompt displayed the selected project. A noninteractive preflight followed by interactive authorization is a design candidate, not proof against policy changes, concurrent cached grants or misleading displays. The [polkit rules documentation](https://polkit.pages.freedesktop.org/polkit/polkit.8.html) warns that retained authorizations can apply to the same action and subject even when details change; a reviewed target policy must avoid retained grants for decision confirmation.
- The review snapshot, sender/session identity, authenticated response, and protected head/revision must be bound under a final commit lock. The broker-private journal currently stores opaque records and does not establish a protected project history, a trusted human selection, or a rollback anchor. Treat the new project-store owner, bus method, fixed service policy and independent tests as a single authorization boundary. Fail closed on unsupported process credentials or session evidence; do not expose an approved decision until real target/human testing succeeds.

Before adopting a Rust bus library, compare its current primary documentation, process credential and Unix-FD support, async cancellation behavior, locked dependency closure, and license notices against the release package. Test the bus integration with disposable peers, no host installation; separately verify actual Polkit, active local session, and human interaction on an Omarchy machine. No dependency was installed for this research.
