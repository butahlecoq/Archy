## Contract

The inventory retains schema 2, but its system_files list is now subject to a stricter gate contract. It must include the fixed x86-64 glibc loader. The generator inspects every packaged ELF, the fixed bwrap, Blender, Python and Node entry points, and the transitive DT_NEEDED closure using descriptor-based readelf; it never runs inspected executables. The gate independently parses bounded ELF headers, dynamic tables and referenced strings after checking package membership, ownership, modes and hashes. It scans all inventoried system ELF as well as payload ELF and requires every candidate library for every DT_NEEDED name in the conservative union of packaged ELF parent directories, supported RPATH/RUNPATH directories, /usr/lib and glibc-hwcaps variants to be present and inventoried. Empty, missing, inconsistent, malformed, unsupported or unresolved coverage fails closed. The union deliberately over-approximates search paths: it covers libraries preloaded by Python as well as ordinary $ORIGIN links, and can reject a runtime containing unused optional libraries.

The gate rejects dynamic loader preload configuration, unsupported interpreter layouts, relative or unsupported search tokens, ELF audit/filter tags and unsupported ELF formats. The static parser does not execute the inspected object. Before bwrap runs outside the sandbox, the gate separately requires its recursive default /usr/lib dependency graph and any hwcaps alternatives, with no prelaunch RPATH/RUNPATH. It launches the verified loader with cache disabled and an explicit /usr/lib library path. Inside the sandbox, the fixed worker and verifier Node use the loader with cache disabled but do not override library paths, preserving packaged RUNPATH priority. No host ld.so.cache, caller PATH or project bytes authorize the list. Production packaging still requires the statically linked gate; author probes used a dynamically linked development gate.

This is a conservative contract for the checked ELF metadata and named CPU entry points, not proof of arbitrary later dlopen, GPU drivers, vendor ICDs, data/config loads, host compromise or a privileged concurrent writer. It assumes the supported x86-64 Arch/glibc layout, immutable root-owned loader, libraries and mount environment, a trusted isolated build namespace, and cleared loader environment. It does not establish compiler, native wheel or distribution notice provenance. Runtime trust and source/license reviews remain pending, trusted review allowlists remain empty, and source identity reports build_ready false.

## Evidence and blockers

In a network-disabled disposable Arch container, a real compiled ELF fixture and the actual gate accepted a matching generated inventory and rejected an empty system list, an omitted system dependency of a packaged Python extension while other entries remained, an omitted loader, an omitted pre-sandbox bwrap dependency, an unlisted hwcaps alternative, loader preload configuration, and an embedded ELF audit hook. The generator also refused a missing fixed entry point and the audit hook. A separate experiment showed why calling ld.so --list is not an acceptable validator: an ELF audit-library constructor executed during listing; the final source does not use that mechanism. A real bind-mount parent swap during generator candidate discovery was denied inside a disposable unprivileged mount namespace. A production-branch IFC verifier/gate fixture reached a marker with a valid inventory and refused tampered Node, bwrap, system dependency and inventory before marker execution; it is synthetic and is not a real orphan transaction or installed runtime.

On this source, 54 packaging tests, nine gate unit tests, strict offline CLI/gate Clippy, formatting and diff checks passed. A regression unit test covers a 21,897,354-byte ELF string table using bounded referenced reads. The original 16 MiB prototype rejected that real string-table size in a superseded Blender libopenvdb, so that failed audit was diagnosed and the arbitrary limit removed.

The current generator was run read-only on a superseded 2.3 GiB staged package in a network-disabled disposable Arch container. It failed closed because libXt.so.6 was missing; a separate exhaustive ELF scan found MaterialX render libraries need libXt.so.6 and libOpenImageDenoise_device_hip.so.2.3.3 needs libamdhip64.so.6, also absent. The earlier optimized development gate audit of that old inventory failed before completion on a Python-preloaded MaterialX library; the candidate subsequently added the conservative payload-directory rule. No final package was rebuilt. A reviewed CPU-only payload policy or properly sourced dependencies, followed by a new authorized offline build and positive native checks, are required. Neither the full service budget, private bwrap/systemd behavior, final IFC worker/Node path, GPU, Omarchy target, human approval, nor legal distribution readiness is established.
