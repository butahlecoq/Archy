## Independent behavior evidence

I ran `cargo test -p archy-authority --locked --offline --quiet` with the handoff's offline target directory, two build jobs, and automatic Rust installation disabled: exit **0**, with 2 library, 1 display, 13 socket boundary, and 8 journal boundary tests passing. Those tests exercise real Linux seqpacket pairs/listeners, peer credentials, ancillary descriptor and oversized-frame rejection, eight human workers with silent peers, hash-checked reads, symlinks, pending recovery, corrupt chains, concurrent appenders, and uncertain-commit replay.

I also built and ran a separate probe from `/tmp/a16-review-sol-probe` against this worktree's authority/core libraries (`cargo run --manifest-path /tmp/a16-review-sol-probe/Cargo.toml --offline --quiet`, same target settings): exit **0**. Its assertions observed:

- A serialized journal event of exactly **65,536 bytes** was accepted, reopened and exactly replayed with the same sequence/hash. A **65,537-byte** event and a 16,384-NUL maximum-escape payload returned `InvalidInput` without creating another file; a following append received sequence 2. The size check occurs after serialization and before nonce/temp-file creation. The journal test suite additionally passed private pending recovery, malformed pending refusal, changed-record refusal, and post-rename sync-failure replay.
- With a real `journal` child and 1,022 filler entries in the proposal store, one valid proposal brought the directory to **1,024 total entries**. A different valid proposal returned `STATUS_FULL`; exact replay and hash-checked read still succeeded. Replacing one filler with `.pending-abandoned` kept the directory at 1,024 and still denied a new proposal. Thus the DESIGN limit is **1,024 total proposal-store directory entries, including pending files and the actual journal directory**. In a clean store with the journal child and no other entries, the effective maximum is **1,023 proposal files**. The journal itself is a separate directory with its own 1,024 committed-event limit.
- A traversal digest returned `STATUS_INVALID`; symlinked store/journal roots were refused. Real seqpacket `OP_DECIDE` packets returned `STATUS_DENIED` on both agent and human channels; a mismatched peer UID was denied; the journal file count was unchanged. Source inspection found the daemon only opens/verifies the journal: it has no append call. `Journal::append` is a public opaque-storage primitive, so its contents alone must never be interpreted as decisions; no socket route projects them to approved state.
