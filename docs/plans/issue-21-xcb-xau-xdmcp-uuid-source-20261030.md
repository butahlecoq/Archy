# Issue #21: historical xcb, Xau, Xdmcp and uuid source handoff

Base: provisional historical inventory candidate `1b10a901dfea3545723e1491601766c7d2b198cf`. Work occurred in a new isolated worktree, with all downloads and keys in `.t/issue21-sources-20261030` outside the repository. The historical inventory is under independent review.

## Bounded plan and result

For each of the four library owners: (1) read the owner, version and ELF hash from the candidate inventory; (2) recover the exact Arch package recipe tag, pinned upstream source and signatures; (3) compare the official archived binary package ELF bytes with the inventory; (4) preserve the package's full notice files and compare them with the upstream source where possible. Each package has its own [evidence note](../evidence/issue21/libxcb-source-notice-20261030.md): [libXau](../evidence/issue21/libxau-source-notice-20261030.md), [libXdmcp](../evidence/issue21/libxdmcp-source-notice-20261030.md), and [libuuid](../evidence/issue21/libuuid-source-notice-20261030.md).

All four exact archived library files matched the candidate inventory SHA-256 values. The three X.Org tarballs matched the SHA-512 values in their exact tagged Arch recipes, and their detached signatures verified. The util-linux `v2.42.4` signed Git tag verified and its commit/tree were recorded. All four archived binary package signatures verified. `.PKGINFO` confirmed each owner/version. All source and package notice comparisons described in the individual notes matched byte for byte. This is source, package and notice evidence for the historical image, not proof that an independent rebuild produces those bytes.

## Verification method

The four recipe repositories were cloned at their named Arch tags. The X.Org archives and `.sig` files came from the `source` URLs in those recipes. The util-linux Git checkout used tag `v2.42.4`. The archived Arch `.pkg.tar.zst` files and detached signatures came from `archive.archlinux.org`. SHA-256/SHA-512 were computed over downloaded files. `gpg --verify` and `git tag -v` used a private GnuPG home populated with keys fetched by exact fingerprint from public key servers; all reported good signatures. Key certification to an independent trust root was not established.

Package members were read with `bsdtar -xOf` in the pinned historical Arch image `sha256:98bafd0772026dd0c92b4beaffe415163272a6b9f21d4f3b089ba89affcc759f`, with read-only package mounts and `--network none`. Each `.PKGINFO`, resolved ELF and shipped license member was hashed. X.Org `COPYING` files were extracted with `tarfile` from the pinned source archives and compared byte for byte to their package members. For util-linux, four shipped `COPYING.*` files were compared to its signed Git tree, and the extra `util-linux-BSD-2-Clause.txt` matched the recipe's SHA-256 pin. The saved recipe, notice and detached signature files are in [package specific directories](../../packaging/arch/issue21-source-notices/). The signed upstream util-linux tag object is also saved there; `git hash-object -t tag` returned `a1d2b6980b84f38b389a6d6dda4a9623f47d13be` for that file.

The change is evidence only. No source or binary package was rebuilt or installed. No runtime recipe, allowlist, `build_ready` flag, current target choice, or other agent's component was changed. Independent review of the candidate inventory, key trust, source-to-binary reproducibility, complete transitive source/header notices (especially the shared code in `libuuid`), distribution obligations and target validation remains open. Changes to the runtime package or build image require a new comparison.
