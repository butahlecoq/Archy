# A21 doctor slices 1–2 handoff

Implemented 2026-10-29 in the CLI only. `archy doctor` and `archy doctor --json` share typed observations and pure policy evaluation. The compatibility manifest approves only the documented Omarchy 4.0.6 upstream identity with an Arch release suffix. Blender and IFC versions are proposals with `evidence_status: unverified`; matching installed metadata remains deferred and cannot make either capability ready.

## Contract

- Report schema: `schemas/doctor.schema.json`, version `1`. Checks are sorted by ID. Unknown observed versions are JSON null. Statuses are `available`, `missing`, `unsupported`, `unavailable`, and `deferred`.
- Exit 0 means native core diagnostic prerequisites matched the reviewed policy. Exit 1 means a required prerequisite is unresolved. Exit 2 is internal report generation failure. Desktop, backend and containment capabilities are separate; `target_acceptance` and all named A21 target gates stay deferred.
- The collector reads `/etc/os-release`, `/proc/sys/kernel/osrelease`, `/sys/fs/cgroup/cgroup.controllers`, and optional `/usr/share/archy/backends.json` as data. Passive reads require a root-owned, non-writable regular file; symlinks are rejected except `/etc/os-release` resolving to `/usr/lib/os-release`. Opens use no-follow and nonblocking flags, verify the opened inode, cap reads at 64 KiB and each probe at two seconds, and share a 15-second collection budget. The CLI adds the existing workspace-pinned `rustix` crate for these file-descriptor flags; no new workspace dependency was introduced. It queries only root-owned, non-writable `/usr/bin/pacman` with fixed `-Q` package arguments and a cleared environment. The subprocess runner creates a dedicated process group, terminates that group on excess output or deadline, and never waits without a deadline for descendant-held pipes. Doctor does not run PATH entries, shell wrappers, workers, mise, bwrap, systemd, network calls, or installation commands. No Archy-owned persistent writes occur.
- Parsed Omarchy upstream version is reported whenever a valid stable-package identity is observed, including unsupported versions and ambiguous or partially unavailable package queries. A prerelease is parsed as a version but remains unsupported. Unknown or malformed versions remain JSON null.
- The optional backend metadata file is an inventory input, not a runtime proof. A mismatched Blender or IFC version is unsupported; a matching proposed version remains deferred until exact artifacts, complete locks, native loader checks and worker smoke evidence exist.
- The shell package and cgroup controller inventory are passive observations. Live plugin API, effective isolation, resource limits, descendant cancellation and user-manager availability remain deferred.
