## Existing Archy contracts: usable now versus prerequisites

[main.rs](../../crates/archy-cli/src/main.rs) currently exposes only `doctor`, `init`, `validate`, `generate`, `evaluate`; inspect parser/source again before implementation. No working project-list, status, open-report, preview, Blender-launch or capabilities command exists.
[doctor.rs](../../crates/archy-cli/src/doctor.rs) and [schema](../../schemas/doctor.schema.json) define `schema_version: "1"`, `host`, `platform`, sorted `checks`, `capabilities`, `ready`, `target_acceptance`, `target_gates`.
Checks contain `id/required_for/status/observed/expected/evidence/reason/remedy`; statuses are `available|missing|unsupported|unavailable|deferred`, nullable observations stay null. Each capability (`core/blender/ifc/containment/desktop`) has `ready/required_checks`.
Doctor exit 0 means core diagnostic prerequisites available; exit 1 still carries a valid report with unmet prerequisites; exit 2 is invocation/internal failure (may carry structured error, not DoctorReport). Global `ready` is not all-capability readiness or acceptance.
`target_acceptance` is always `deferred`; `desktop.plugin-api` and containment enforcement remain deferred. Backend metadata is not live Blender/IFC health. Do not suppress the panel because desktop readiness is false.
Observed existing `target/debug/archy doctor --json` on this WSL host: schema 1, environment wsl, readiness false, Omarchy identity null, target acceptance deferred; binary was not rebuilt, so this is a sample, not source-build validation.
Reuse [RunManifest/Artifact/RunReceipt](../../crates/archy-core/src/run.rs), [storage](../../crates/archy-core/src/storage.rs), [run_integrity](../../crates/archy-cli/src/run_integrity.rs), [report rendering](../../crates/archy-report/src/lib.rs); reports currently provide JSON/Markdown. Do not promise HTML, preview or blend artifacts merely because workers exist.
Important prerequisite: `verify_run()` calls `ProjectStore::lock()`, which can create `.archy/{staging,revisions,lock}`. Extract/reuse verification logic behind a bounded noncreating snapshot reader; do not call this path from passive status.

## Coordinator reconciliation: transport completion

The first S1 independent review reproduced a close/reopen-before-reaping refresh loss. Its author has a frozen fix and a real child-process regression; scoped rereview is pending. A temporary `streamsComplete: false` path prevents every report from being displayed. Ruling: this is an honest intermediate gate, not completion of the useful doctor panel. The final implementation still must display complete valid exit-0/1 reports and reject incomplete or corrupted output.

Primary-source checks on 29 October 2026 refine the transport uncertainty:

- [Quickshell v0.2.1 Process implementation](https://github.com/quickshell-mirror/quickshell/blob/v0.2.1/src/io/process.cpp) connects QProcess output signals to parser callbacks, ends both parsers before emitting `exited`, and exposes no separate SplitParser completion signal. This is source behavior at that tag, not installed-host evidence.
- [Quickshell v0.2.1 SplitParser implementation](https://github.com/quickshell-mirror/quickshell/blob/v0.2.1/src/io/datastream.cpp) converts individual byte chunks to strings when the marker is empty. Inference: UTF-8 split across chunks can be decoded separately; the Node harness's StringDecoder does not reproduce that behavior. The final transport must prevent or detect character corruption, including non-ASCII host/project text and non-BMP characters.
- [Qt v6.10.0 QProcess implementation](https://github.com/qt/qtbase/blob/v6.10.0/src/corelib/io/qprocess.cpp) explicitly attempts to drain both output channels in `_q_processDied` before process completion signals. This strengthens the ordering argument for that source profile. It does not prove which Qt the target has, nor establish live QML behavior on an unknown profile.

Next evidence: a generic headless Quickshell process harness in an isolated Arch container on WSL, recording the actual Quickshell/Qt package versions and testing final output, fragmented Unicode, close/reopen, missing executable, timeout and oversized streams. The new development image contains Quickshell 0.3.2 and Qt 6.12.0; [the 0.3.2 parser](https://github.com/quickshell-mirror/quickshell/blob/v0.3.2/src/io/datastream.cpp) retains the individual-chunk conversion issue. This is a distinct development profile, not an inferred target baseline.

Ruling: use lossless ASCII escaping for doctor and desktop JSON wire output, keeping parsed values and schemas identical. JSON escapes must handle BMP and non-BMP characters and be tested at arbitrary chunk boundaries. This presentation change must not alter persisted canonical source, variant, evaluation, report or golden artifact bytes. Pair it with source/profile ordering checks and the actual QML harness before permitting valid reports; ASCII alone is not evidence of stream completion. The Rust CLI owner and QML owner have separate write scopes. Do not substitute unbounded line collectors or timers for a proven bound/completion rule. The actual Omarchy lifecycle, theme and installed-profile gates remain deferred.
