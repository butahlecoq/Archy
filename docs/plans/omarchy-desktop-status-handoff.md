## Contract and risks

The only operations accepted from capabilities are `project_status` and `run_status`. The user types one absolute local manifest path in a Qt `TextField`; the plugin neither scans for nor persists projects and never accepts a path in the summon payload. Fixed process prefixes are `/usr/bin/archy desktop capabilities --json` and `/usr/bin/archy desktop status --project PATH --limit 20` with optional typed `--run ID`/`--cursor TOKEN`, ending in `--json`. Path spaces are preserved as one argv item. Run IDs must be in the currently displayed verified page; cursors match the published opaque v1 form. No shell, PATH resolution, arbitrary executable, job control, approval, or H3 opener is wired.

The model accepts only exact v1 object shapes, ASCII stdout, normal exit 0 and empty stderr. It caps capabilities at 64 KiB and status at 1 MiB before accumulation, arrays/strings at finite display limits, and validates descending revisions, aggregate check result, verified artifact metadata, and `backend_jobs: unknown`. The QML process uses cwd `/`, cleared environment with locale only, a 20-second deadline, TERM then KILL after 250 ms, one in-flight child, and request generations. Changing the manifest cancels the old child; close discards stale results. A stale page cursor leaves the prior view visibly stale and offers an explicit first-page refresh. Artifact metadata grants no launch authority. Report, preview, and Blender controls stay disabled until H3.

Round-1 fix: the active probe carries the exact `--run` selector used in its argv. For an omitted selector, a nonempty page must select its first run with the same complete summary; an empty page must select null. For an explicit selector, the selected summary must use that ID and match its page summary when present. The H2 CLI searches the full accepted history for an explicit run, so an off-page selected run remains valid. This checks external JSON at the model boundary before QML replaces the displayed status.

The known limits are a generic Quickshell 0.3.2 / Qt 6.12 container profile, no Omarchy Main/theme execution, and no installed Arch package identity. The frozen published CLI binary used in one harness test is mapped read-only at the fixed path; that is development-image evidence, not target acceptance. Aggregate `all_required_checks_passed` is the only per-run check signal in H2; individual evaluation checks are not exposed by this status contract. Backend jobs remain `unknown` without A16 supervisor observations. The UI does not infer live progress from run history.
