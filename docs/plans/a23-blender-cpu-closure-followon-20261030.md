## CPU evidence and execution correction

G06 and OM-A23-01 require the CPU journey; GPU evidence is optional and separate. The current worker explicitly selects Cycles CPU and disables denoising. In a network-disabled Arch container without /dev/dri, /dev/kfd, libXt.so.6 or libamdhip64.so.6, three distinct seed-42 generated L-shaped variants ran the current worker directly with no host ld.so cache. Each produced a parsed GLB, three CRC-checked/decompressed 512-by-512 PNGs and matching worker artifact hashes. None of these three glibc loader traces mentioned libXt.so, libamdhip64 or the HIP denoiser. This is bounded observation of those inputs, not proof about arbitrary dlopen, all shapes, target behavior or the full golden journey.

The prior closure candidate launched Blender through ld-linux explicitly. ## ELF security review follow-on

Both independently reported issues were reproduced before changes. A real compiled ELF in an unrelated directory falsely satisfied another requester's DT_NEEDED in both the generator and gate, while the actual glibc loader could not resolve it. A separate ordinary malformed-ELF regression changed PT_DYNAMIC's virtual address without changing its file offset; the old parser accepted it.

The Linux loader documentation at https://man7.org/linux/man-pages/man8/ld.so.8.html distinguishes inheritable DT_RPATH from direct-only DT_RUNPATH and documents cache, preload and hardware-capability search. Each ELF requester must now have a matching dependency through its own effective RPATH/RUNPATH or the fixed system directory; an unrelated directory cannot satisfy it. Potential inherited legacy RPATH alternatives are still conservatively checked for inventory coverage, and a requester's RUNPATH suppresses that inherited check. A real parent-RPATH fixture demonstrated that an unlisted inherited alternative is rejected and a listed one accepted; a separate RUNPATH fixture matched glibc behavior. The current all-ELF policy deliberately refuses a dependency resolvable only through an ancestor: it does not yet model a complete loader-parent/link-map graph and can reject a valid runtime. This limitation is explicit; do not call it complete arbitrary dynamic-load coverage.

The gate now validates PT_DYNAMIC and string-table virtual-to-file mappings through PT_LOAD, rejects inconsistent, ambiguous, out-of-range or misaligned segments, and reads referenced strings with bounds. An additional real ELF fixture marked NODEFLIB reproduced a false acceptance in both initial fixes: glibc skipped /usr/lib while the candidate counted it. The generator and gate now reject NODEFLIB rather than assuming default search applies. The real pinned Blender executable and libopenvdb ELF passed the segment parser in a disposable container. A gate-level corrupted PT_DYNAMIC fixture was rejected. A bind-mount swap against generator candidate discovery was refused in a disposable unprivileged namespace. All payload bytes and listed system files still require root-owned immutable paths and hashes; external runtime dlopen, host/root compromise and post-check privileged replacement remain outside this evidence.
