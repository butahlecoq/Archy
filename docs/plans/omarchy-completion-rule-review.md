# A22 S1 doctor completion rule: independent preflight

**Verdict: approve the proposed rule for implementation and native retest on the observed Quickshell 0.3.2 / Qt 6.12.0 development profile.** The current product still passes literal `false` to `Model.complete()`, so valid exit-0/1 reports remain unavailable. This preflight does not mark S1 implemented or accept an Omarchy target.

## Basis

The immutable native harness runs the actual `DoctorProcess.qml` and `DoctorModel.js` with a fixed `/usr/bin/archy doctor --json` command. Its valid fixture cases are red only because `streamsComplete` is literally false; negative, timeout, start failure, close/reopen, and Unicode split observations are recorded in `omarchy-plugin-handoff.md`. The ordering probe saw full fixture stdout before `exited`, and the read-only frozen CLI probe saw 6,778 ASCII stdout bytes, empty stderr, a parseable schema-1 report, and exit 1 before `exited`. The CLI ASCII serializer independently passed its roundtrip tests. I reran the focused Node model suite: 7 passed.

At the [Quickshell v0.3.2 Process source](https://github.com/quickshell-mirror/quickshell/blob/v0.3.2/src/io/process.cpp), `onFinished` ends both parsers before emitting `exited`. The [Qt 6.12.0 QProcess source](https://github.com/qt/qtbase/blob/v6.12.0/src/corelib/io/qprocess.cpp) calls both channel reads before `processFinished`, which emits `finished`. Together with the observed ordering, this supports interpreting `exited` as completion of the bounded parser text **for this tested source/runtime profile and the trusted fixed producer**. This is an inference from that source and native evidence, not a generic child-exit or EOF guarantee.

## Required implementation conditions

1. On `exited`, accept only the active probe/generation while the panel is open, with a normal process exit of code 0 or 1, no cancellation, timeout, start failure, encoding or byte-limit failure. Keep the existing single in-flight slot, 20-second deadline, 64 KiB per-stream cap, stale-result discard, and close/reopen behavior.
2. Enforce ASCII on every stdout chunk before accumulation; the current model rejects U+FFFD but does not reject other non-ASCII text. Require empty stderr for a valid report, as the fixed CLI producer emits no stderr on normal doctor exits. Parse exactly one full JSON document and apply the existing strict `DoctorReport` shape and finite limits. A syntactically complete prefix is acceptable only insofar as it is the entire fixed producer's single document; no arbitrary-child trust is implied.
3. Record the producer contract beside the rule: packaged `/usr/bin/archy doctor --json` writes one bounded ASCII JSON report on stdout and flushes it before normal exit 0/1, writes no stderr for those exits, and does not hand its stdout/stderr to a surviving child. Keep the fixed absolute argv and controlled environment; bind runtime acceptance to the reviewed packaged binary and Quickshell/Qt profile. Do not use `exitStatus` alone as stream proof or extrapolate this rule to other commands or unknown runtime versions.
4. After changing QML, rerun the **actual native component** matrix: valid 0/1 must display the report, while exit 2, crash, malformed/truncated JSON, stdout/stderr flood, timeout, start failure, split Unicode, and close/reopen remain fail-closed or correctly refreshed. Repeat the real frozen CLI case and check report fields, empty stderr, ASCII bytes, and event ordering. The existing red valid-report test must turn green before calling S1 useful.

The harness is generic Quickshell in an Arch container on WSL and does not load the Omarchy shell. Installed Omarchy versions, lifecycle, theme, and target runtime acceptance remain deferred under OM-A22-01. No production file was changed in this review.
