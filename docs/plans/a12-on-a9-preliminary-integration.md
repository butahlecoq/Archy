## Contract for later MCP reconciliation

- Public Rust entry point: `archy_cli::export_ifc(ExportIfcInput) -> Result<archy_core::RunReceipt, ArchyError>`. `ExportIfcInput` has `project: PathBuf`, `source_run: Option<String>`, `variant_id: String`, and `mutation: MutationOptions`. The receipt has `run_id`, `revision`, `manifest_sha256`, and `path`. This returns a `RunReceipt`, not the generation/evaluation `WorkflowReceipt`.
- `MutationOptions` has `idempotency_key: Option<String>`, `expected_project_revision: Option<u64>`, and `destination: String` (default `runs`). An explicit key requires an explicit expected revision. Same-key replay verifies the stored export before returning its receipt; different selectors under a recorded key conflict.
- `source_run: None` selects the most recent accepted generation or edit, then validates it. It does not search backward for an eligible v1 run if that latest run is canonical v2. Selected source must be an accepted historical JSON v1 generation or edit with the requested variant. Canonical v2 and YAML sources currently return a `source_run` schema error before the worker starts.
- The persisted operation is `export-ifc`, with `parent_run_id` set to the source and `parent_variant_id` set to the variant. It writes `design-manifest.json`, `ifc/model.ifc`, `ifc/validation.json`, `ifc/response.json`, and the bound source/variant/evaluation snapshots. The manifest is DRAFT and schematic only. `design_manifest_schema()` generates `schemas/design-manifest.schema.json`; verification reopens the stored IFC through the pinned reader.
- CLI equivalent: `archy export-ifc --project PATH --variant ID [--run ID] [--idempotency-key KEY --expected-project-revision N] [--destination runs] [--json]`. The MCP adapter should call the public Rust entry point and preserve its `ArchyError` and receipt semantics; it should not bypass accepted-run verification or invoke the worker directly.
