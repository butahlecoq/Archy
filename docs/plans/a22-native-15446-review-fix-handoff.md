# A22 independent review fixes

Base: `15446eeaf316846936a093377041b8c1d2874092`. This is the same isolated candidate described by `a22-native-15446-handoff.md`, with the three reproduced review findings addressed. No integration with the separately prepared `1e` head is claimed.

Install now stages every checked file in a private directory and publishes that directory through Linux `renameat2(RENAME_NOREPLACE)` relative to an opened plugin parent. It never writes through the final destination path. State publication uses a no-follow, exclusive temporary file and hard link, and records the published directory's device and inode. Repeated install and uninstall reject a different directory even if its contents are identical. Uninstall moves the entry to an exclusive backup and compares that moved inode with the inventoried handle before deleting ownership state; if it differs, it tries to restore the entry and refuses. The earlier state format is intentionally unsupported by this new pre-release candidate; an existing experimental installation needs manual inspection before migration.

`desktop open` keeps fixed viewer executables and arguments and the verified private artifact copy. It observes the launched viewer for 250 ms, returns a bounded stderr diagnostic on immediate nonzero exit, and gives a handoff receipt if the viewer exits successfully or remains running beyond the window. The receipt does not prove display or a later viewer outcome.

Race tests interleave destination replacement at publication, after state publication, and at uninstall's move, and test same-content inode replacement. The original preview, idempotence, rollback, collision, edit, missing-source, and symlink tests remain. A Rust unit test covers immediate viewer failure and bounded successful handoff. See the final patch hash and check outcomes in the re-review request.

Linux does not expose an atomic compare-inode-and-rename operation. A concurrent actor with write access to the user plugin directories can still move an entry before the post-move identity check or replace the final name after the last check. The code preserves the state on detected uninstall mismatch and avoids deleting a differently identified directory; restoration can fail if the actor occupies the name. Run transactions without another writer in those directories. The fixed viewer can fail after the observation window. Actual Omarchy 4.0.6 installed shell and viewer validation remain deferred.
