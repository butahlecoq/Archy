## Design and exact inputs

`packaging/arch/runtime_snapshot.py` deterministically freezes worker source, the package tool/notices, IFC lock, and exact A12 reader/bridge bytes into an archive. `runtime_recipe.py` checks input files and generates a local-source Arch `PKGBUILD` whose sources all have literal SHA-256 entries. `runtime.py` stages a final-prefix CPython build, official Blender archive, a private bwrap from an Arch-signed package blob, all 15 matching IFC wheels, official Node, npm-lock-matched web-ifc, verifier scripts and notices. It rejects archive links/escapes, unexpected wheel closure, wrong input hash, duplicate output paths and unsafe payload types. No WSL venv is copied. It inventories every regular payload file with path, SHA-256 and mode, plus the disposable Arch image's linked CPU executable/Python-extension ELF system library closure. The gate checks full payload membership, roots/modes/hashes, required backend entries and system ELF hashes before launch, and uses fixed private Blender/Python/bwrap paths. `--audit-runtime` is read-only prelaunch inventory validation for disposable containers.

The independent v4 code review reproduced an incomplete snapshot succeeding with no verifier files. `runtime-inputs.json` now pins every verifier and worker source file; `runtime_manifest.py` requires the three exact verifier paths, essential workers and lock, exact directory membership, notice hashes, and separate A12 and distribution review evidence. A review document is itself hashed and must contain `Runtime-Input-Set-SHA256: <digest>` binding all pinned worker/verifier bytes, the snapshot, recipe and staging tools, and notices. `python3 packaging/arch/runtime_manifest.py --source . --identity` computes that digest while reporting `build_ready: false`; it does not approve anything. The guard module contains separate empty trusted review-hash allowlists and is excluded from the bound digest to avoid a circular hash; the guard and its eventual allowlist changes require independent source review. The current manifest marks packaging-bound A12 review and distribution review `pending`, so real snapshot creation fails before opening an output. After the reviews actually pass, the owner must install their exact evidence documents, set reviewed statuses and hashes, add the hashes to the separately reviewed guard allowlists, and update the verifier/worker manifest together. The digest binding prevents stale evidence after a source change; it does not by itself authenticate a reviewer or establish legal compliance.

Snapshot creation validates all inputs before writing; recipe generation validates the complete source archive and matches the snapshot's recipe/manifest tools to the generator. The generated `build()` repeats the tree check before compiling CPython, and package staging checks again. Tests cover absent and changed verifier or worker inputs, omitted and unlisted paths, symlinks, pending or stale reviews, incomplete archives, and deterministic valid synthetic reviewed fixtures. The prior `6978...`/`4cbc...` pins are superseded; no build-ready snapshot or final package has been produced from the reviewed `ae7` source and b987 Blender inputs.

The preflight tools are invoked by fixed `/usr/bin/python3 -I -S -B` in the generated recipe; their local trusted tool directory is inserted explicitly, and a hostile `PATH`/`PYTHONPATH`/`PYTHONHOME` fixture cannot execute `sitecustomize`. A synthetic reviewed fixture generated a syntactically valid recipe with preflight before CPython `configure`; this fixture has test-only trust hashes and is not a real approval. The prior incomplete source archive was rejected by the new recipe generator before a PKGBUILD was written.
