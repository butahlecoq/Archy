# A09 systemd user-service scratch FD probe handoff

Date: 2026-10-29. Owned files: `tests/security/systemd_scratch_fd_probe.py`, its mode regression, and this handoff. The probe reuses the fixed `SCM_RIGHTS` receiver and tmpfs constants in `tests/security/scratch_fd_probe.py` without editing it. It runs only a disposable Python fixture through `/usr/bin/systemd-run --user`; no Blender, IFC, production worker, bwrap, sudo, system unit, dependency, lockfile, commit, push or agent was involved. The original evidence below is a historical snapshot; see the round1 addendum for the current source.

## Mechanism tested

The parent creates a UUID-scoped transient user service and private disposable host mountpoint. It supplies one end of a private Unix `SOCK_SEQPACKET` socket as `systemd-run --pipe` stdin. The unit has `TemporaryFileSystem=<mountpoint>:size=65536,nr_inodes=8,mode=0700,nosuid,nodev,noexec`, `RuntimeMaxSec=20s`, `MemoryMax=268435456`, `MemorySwapMax=0`, `TasksMax=16`, `KillMode=control-group`, and `TimeoutStopSec=2s`; `--wait --collect --expand-environment=no` are set. All executable paths are fixed. No caller-supplied command, mount or unit name is accepted.

Before any fixture output write, the service opens its private tmpfs directory and sends exactly one directory FD plus a bounded evidence frame over stdin using `SCM_RIGHTS`. The parent receives it with `MSG_CMSG_CLOEXEC` and rejects extra/truncated/wrong-type ancillary data. Before sending the bounded `GO` token, the parent compares the FD identity and `statvfs` byte/inode capacities, checks the service PID's mountinfo for tmpfs and `nosuid,nodev,noexec`, checks `systemctl show` values, reads the actual service `memory.max`, `memory.swap.max`, `pids.max` and `cgroup.events`, and verifies the scratch directory is empty. The helper then writes only a small `payload.bin` into that tmpfs and exits. Python bytecode writes are disabled for both parent and service.

After `systemd-run --wait` exits, the parent requires an inactive service and an empty or removed service cgroup before opening `payload.bin` relative to the retained FD. It checks exact bytes and SHA-256, empty host backing directory, unchanged outside sentinel, FD closure (`EBADF`), parent FD count, and source-directory inventory. The UUID service is stopped in cleanup if still present; the manager's `--collect` removed it in the passing run. Socket waits, manager queries, service runtime and final communication have fixed deadlines within the 30-second probe budget, with scoped process-group teardown on error. Unsupported properties, missing FD forwarding or missing cgroup evidence fail as `status=unavailable`; the script has no fallback mode.

The first live run also passed the transport and limits, but importing the shared helper created a Python bytecode cache outside scratch. That generated cache was removed. The fixture now disables bytecode writes and checks the source-directory inventory; the final run above is the clean result. The earlier [kernel FD probe](scratch-fd-probe-handoff.md) separately demonstrated real byte and inode `ENOSPC` with the same tmpfs capacities. This service probe measures the effective capacities and cgroup limits before token release; its post-token writer intentionally creates only the tiny fixture, so it does **not** claim a second systemd-service ENOSPC run.

## Remaining gates

This is evidence that this WSL user manager forwards the control socket through `--pipe`, enforces the selected mount/cgroup properties, and allows a retained FD read after service teardown. It does not prove the eventual packaged gate helper, descriptor peer authentication, whole-worker isolation, all writable mount accounting, OOM/timeout/fork/escape behavior, bwrap restrictions, independent artifact decoding, storage publication, or actual Omarchy support. A production supervisor must verify those policies and fail closed if unavailable.

## Round1 mode check

The pre-token receiver now checks that the passed directory FD is owned by the parent real UID and has exact mode `0700`, including no special bits. `/usr/bin/python3 -B tests/security/systemd_scratch_fd_probe.py` exited 0 on WSL and reported `scratch_uid=1000`, `scratch_mode=0700`, byte capacity 65536, inode capacity 8, inactive service, absent cgroup and the same payload SHA-256 recorded above. The fixture's parent real and effective UIDs were both 1000. This is evidence for that user-manager environment; other user namespace mappings must be checked at their own boundary.

`/usr/bin/python3 -B tests/security/systemd_mode_regression.py` exited 0 and reported `{"status": "pass", "mode": "0777", "start_token": "not_reached"}`. It makes a disposable copy, changes the tmpfs mount mode to `0777`, and replaces the token send with a failure sentinel. The actual service probe returned exit 1 with `status=unavailable` and `scratch directory private mode must be 0700`; it did not reach the token sentinel. Before the fix, the same mode mutation exited 0 and reported `pass`. Both runs used UUID user services and removed their temporary directories. This test does not assert a production security boundary or Omarchy support.
