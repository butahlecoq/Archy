Source-file citations below use commit permalinks to `6536`; live GitHub state and external documentation are identified separately. Recheck all evidence for each later candidate.

**Status key:** **Verified** means the named predicate was observed on the named revision and platform. **Pending** means some relevant evidence exists but the whole predicate is unmet. **Failing** means current published behavior demonstrably misses a required predicate. **Not yet tested** means no direct test on the required platform or artifact was found. A fixture, review note, CI success, or mock result is evidence only for what it actually ran. Rows marked pending, failing or not yet tested block release. A required failure cannot become a documented exclusion without a recorded scope change in an ADR, specification and tests. The §7.2 release rule still requires **every** required acceptance test, a clean installation, no unrestricted agent code execution by default and an accurate README.

## Evidence capture and review rule

For each promoted row, attach: candidate full SHA and source tree, spec revision, machine/OS and Omarchy version, CPU/GPU, Blender/IfcOpenShell/reader versions, locked dependency identities, exact invocation and exit code, UTC time, raw output, run IDs, hashes and parsed/visual result. Use a commit permalink for source and a retained hash inventory for files; recheck any live CI/issue/settings link at the final candidate. Do not cite a mutable `feat/release-0.1` URL as a frozen source. The independent reviewer must inspect the actual artifact and result, not only this matrix. The initial matrix received an independent review with findings; this corrected slice awaits rereview.
