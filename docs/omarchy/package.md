# Core Arch package foundation

## Backend runtime candidate

`packaging/arch/runtime_snapshot.py`, `runtime_recipe.py`, and `runtime.py` build a separate `archy-runtime` package from a deterministic worker-source archive and checksum-pinned Blender, CPython, Node, bubblewrap, IFC wheel, and web-ifc inputs. The recipe builds CPython for `/usr/lib/archy/runtime/python` and stages real backend executables and modules at fixed final paths. It does not move a development venv. The package's `inventory.json` is generated from the staged payload; A09's gate audits its listed paths, hashes, modes, root ownership, exact required entries and the payload tree. The inventory also pins the build image's linked CPU ELF system libraries. The recipe and exact commands/evidence are in [the runtime handoff](../plans/runtime-packaging-handoff.md).

Snapshot and recipe preflight require complete pinned worker/verifier inputs and evidence for A12 and distribution reviews. Those reviews are currently open; the checked-in source manifest is deliberately not build-ready. The core package's optional runtime dependency and doctor checks refer to `archy-runtime` and its private bwrap. Package ownership alone leaves containment deferred until the inventory and target enforcement are validated.

The verifier is packaged privately at `/usr/lib/archy/runtime/ifc-verifier`, with Node at `/usr/lib/archy/runtime/node/bin/node` and bubblewrap at `/usr/lib/archy/runtime/bin/bwrap`. The A12 export caller uses these fixed paths and the runtime package owns the verifier files; the combined installation and sandbox still require verification. Neither a successful container package build nor the runtime audit means that systemd/bwrap service execution, GPU rendering, final IFC publication, or Omarchy has passed. Native dependency and source/notice closure still needs independent review before distribution.

The core package recipe stages `/usr/bin/archy`, schemas, the reviewed doctor compatibility data, Archy's MIT license, and generated third-party notices and inventory. `packaging/arch/files.txt` is the allowlist. It also stages the standalone Quickshell plugin at `/usr/lib/archy/omarchy/plugin/`, the local `install.py` and `uninstall.py` scripts beside it, and optional templates under `/usr/lib/archy/omarchy/templates/`. The scripts run only when a user invokes them and require a host Python 3 interpreter; the package has no install or uninstall hook. The package contains no worker, Python runtime, development venv, home configuration, project data, or service. Backend runtime provisioning and desktop enablement remain separate work. Installed CLI execution does not use mise, Cargo, or a venv.

`packaging/arch/notices.py` admits the exact `archy-cli` normal dependency graph from offline locked Cargo metadata. For each registry crate, it matches the Cargo.lock source checksum to the vendored checksum manifest, verifies every selected top-level license/notice file hash, and records package, version, license metadata, source hash, selected text paths, and text hashes. Seven primary upstream files fill the four crates without cached license texts. Their exact repository commits, Git blob IDs, immutable URLs, and SHA-256 hashes are pinned in `notice-inputs.json`; admission checks each copied file and its commit against the vendored crate's `.cargo_vcs_info.json`. It also verifies locally copied Rust 1.99.1 standard library copyright and license texts. The worktree's actual offline normal graph now admits 89 crates and emits 173 crate text entries plus three Rust standard library texts. The generated PKGBUILD invokes admission before the offline Rust build, and package staging checks the bundle against its inventory hash. The prior development package predates this gate and stays private; its 17-file inventory is evidence for that earlier artifact only. Notice presence and crate license metadata do not by themselves establish complete linked-code or legal compliance.

`packaging/arch/package.py stage` takes an existing disposable destination root, a built binary, and both generated notice files. Its manifest must include both reserved notice destinations. It checks the bundle against the inventory and stages those exact validated bytes, with a 16 MiB bundle limit and 2 MiB inventory limit. It rejects source links/special files, destination links, escapes, duplicate paths, and overwrites. It opens source and destination components without following links, holds directory descriptors while creating files, and uses those descriptors and file identities for rollback. It emits each staged file's mode and SHA-256. A failed stage removes only files it created. Use its JSON output to inspect the proposed owned paths. Removing those paths in a test is only an ownership simulation; `pacman -R` behavior requires a real target transaction.

No release source is frozen. When an identified source archive containing `Cargo.lock` and the package tooling is supplied, run `python3 packaging/arch/package.py recipe --archive /absolute/path/source.tar.gz --source-id vX.Y.Z --sha256 <verified archive digest> --output /disposable/path/PKGBUILD`. The generator verifies the archive digest, root, lock, and required notice manifest entries before writing. It rejects an existing output. The generated recipe builds with Cargo `--offline --locked`, `CARGO_NET_OFFLINE=true`, and `RUSTUP_AUTO_INSTALL=0`, then stages into `$pkgdir`. It disables makepkg's optional debug split so this bounded build emits only the core package. An Arch build needs a separately prepared, reviewed Cargo dependency cache or vendored snapshot; the recipe never downloads dependencies during build. The local source archive is checked again by makepkg's `sha256sums` mechanism. A content-addressed development snapshot was built in an Arch container; it is not a released revision or Omarchy acceptance.

The built Arch ELF needs `libc.so.6`, `ld-linux-x86-64.so.2`, `libm.so.6`, and `libgcc_s.so.1`, with no RPATH/RUNPATH entry. In the inspected Arch image the first three belong to `glibc`, and `libgcc_s.so.1` belongs to `libgcc`; the recipe declares those two runtime packages. The final `readelf --version-info` shows nonweak GLIBC requirements through `GLIBC_2.35`, a weak `GLIBC_2.39` reference, and GCC requirements through `GCC_4.2.0`. This container evidence does not establish Omarchy ABI compatibility or all transitive runtime requirements. Rust license metadata and cached license files need an independent distribution audit, including bundled code and exception licenses. MIT for Archy does not relicense dependencies or backend tools.
