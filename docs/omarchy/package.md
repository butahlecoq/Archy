# Core Arch package foundation

The core package contains `/usr/bin/archy`, schemas, the reviewed doctor compatibility data, and Archy's MIT license. `packaging/arch/files.txt` is the allowlist. It contains no worker, Python runtime, development venv, Quickshell plugin, home configuration, project data, service, install hook, or uninstall hook. Backend runtime provisioning and desktop enablement remain separate work. Installed CLI execution does not use mise, Cargo, or a venv.

`packaging/arch/package.py stage` takes an existing disposable destination root and a built binary. It rejects source links/special files, destination links, escapes, duplicate paths, and overwrites. It opens source and destination components without following links, holds directory descriptors while creating files, and uses those descriptors and file identities for rollback. It emits each staged file's mode and SHA-256. A failed stage removes only files it created. Use its JSON output to inspect the proposed owned paths. Removing those paths in a test is only an ownership simulation; `pacman -R` behavior requires a real target transaction.

No release source is frozen. When an identified source archive containing `Cargo.lock` and the package tooling is supplied, run `python3 packaging/arch/package.py recipe --archive /absolute/path/source.tar.gz --source-id vX.Y.Z --sha256 <verified archive digest> --output /disposable/path/PKGBUILD`. The generator verifies the archive digest, root, and lock before writing. It rejects an existing output. The generated recipe builds with Cargo `--offline --locked`, `CARGO_NET_OFFLINE=true`, and `RUSTUP_AUTO_INSTALL=0`, then stages into `$pkgdir`. It disables makepkg's optional debug split so this bounded build emits only the core package. An Arch build needs a separately prepared, reviewed Cargo dependency cache or vendored snapshot; the recipe never downloads dependencies during build. The local source archive is checked again by makepkg's `sha256sums` mechanism. A content-addressed development snapshot was built in an Arch container; it is not a released revision or Omarchy acceptance.

The built Arch ELF needs `libc.so.6`, `ld-linux-x86-64.so.2`, `libm.so.6`, and `libgcc_s.so.1`, with no RPATH/RUNPATH entry. In the inspected Arch image the first three belong to `glibc`, and `libgcc_s.so.1` belongs to `libgcc`; the recipe declares those two runtime packages. The final `readelf --version-info` shows nonweak GLIBC requirements through `GLIBC_2.35`, a weak `GLIBC_2.39` reference, and GCC requirements through `GCC_4.2.0`. This container evidence does not establish Omarchy ABI compatibility or all transitive runtime requirements. Rust license metadata and cached license files need an independent distribution audit, including bundled code and exception licenses. MIT for Archy does not relicense dependencies or backend tools.
